# 第五关上篇「跃」· 角色贴图规格（已落地版）

> 结论先行：**只需要 1 张整图**（再加 1 张静态立绘给结算页）。
> 尾鳍、残影、摆动、雾化全部由程序从这张整图上算出来。

这份文档已按实际情况改过一次。上一版要求出 4 张同画布分层图，
但**用 AI 生图做不到** —— 同一个角色跑两次，比例、光照、线宽都会变，
分层图对不上，静止状态就和原画不一样了。所以改成「一张整图 + 程序切件」。

## 1. 实际采用的文件

放在 `img/sea/`：

| 文件 | 内容 | 用途 | 状态 |
|---|---|---|---|
| `whale.png` | Q 版鲸，横向游动，朝右 | 上篇水下战斗中的主角 | ✅ 已接入 |
| `whale-sing.png` | 鲸鱼少女 | 只用于结算页 / 图鉴等静态场合 | ✅ 已存，待关卡接入 |

两张都是 **1536 × 1024**、透明背景、由白底 JPEG 自动抠出。

### 为什么少女不做动态

她是人形：长发、裙摆、四肢、大眼。一张图做形变必然崩成硬纸板 ——
头发会被拉成塑料片，裙摆会穿模。这类素材只能用**整体平移 + 缩放 + 淡入淡出**。
把它放在结算页那种不需要动的场合，是最合适的用法。

## 2. 出图要求（下次还要出图时按这个来）

给 AI 生图模型的提示词要点：

```
chibi anthropomorphic humpback whale character, full body, strict side view facing right,
flat uniform white background (#FFFFFF), no gradient, no drop shadow,
cute game character illustration, cel-shaded with soft gradients and clean crisp outline,
big head, large expressive eye with catchlight, deep indigo-blue back, pale cream belly,
small rounded pectoral fin pointing downward,
large tail flukes fully spread out behind the body, completely separated from the body silhouette,
soft rim light from the upper left,
no water, no bubbles, no splash, no text, no props,
wide landscape composition 3:2
```

**硬约束（不满足就要返工）：**

| 项 | 要求 | 原因 |
|---|---|---|
| 尾鳍 | 完全张开在身体后方，**不与身体重叠** | 尾鳍要单独转，压在身下切不出来 |
| 胸鳍 | 下缘完整可见，不被身体挡掉下半截 | 同上 |
| 姿态 | **正侧面朝右** | 四分之三侧会让剪切轴失效 |
| 背景 | 纯白或纯色块，**无渐变、无投影、无地面** | 渐变背景抠不干净 |
| 光向 | 左上方（水面方向） | 场景的水下光从上来，冲突会假 |
| 特效 | **不要画水流、气泡、水花** | 它们会跟着角色一起转，非常出戏 |
| 比例 | 3:2 横构图，1536×1024 起 | 竖构图没有横向游动的空间 |

最后一条踩过坑：第一版素材在鲸身周围画了淡蓝色水流和气泡，
抠图时得用「青色连通块识别 + 多轮迭代」才清得掉，还误伤过少女的头发高光。

## 3. 白底图怎么变成透明 PNG

工具：`shots/cutout.cjs`（开发用，`shots/` 在 .gitignore 里）

```bash
node shots/cutout.cjs
```

它不是「按白色阈值切」，理由很硬：

- 鲸的腹部本身就是奶白色 `(250,245,238)`，和背景 `(255,255,255)` 几乎同色，
  任何灰度阈值都会把肚子一起削掉；
- 所以先做**从图像四边出发的连通泛洪**：只有和画面边缘连通的白才是背景，
  被描边围起来的白（腹部）一律保留；
- 挂在角色外面、被身体挡住的水花不连通，再用「偏蓝 + 够亮 + 面积」三条件整块识别；
- 最后「只保留最大连通块」兜底 —— 角色在拓扑上一定是一个整块，散的都是气泡和噪点。

边缘处理只作用于紧贴背景的一圈：从白底反解原色（去白边），内部像素一律 `alpha=255`。

两张图参数不同，这是必须的：

| | `whale.png` | `whale-sing.png` |
|---|---|---|
| 泛洪亮度下限 | 168（能吃淡蓝水花） | 215（只吃纯白） |
| 青色清理 | 开（4 轮迭代） | **关**（她的头发高光就是浅蓝，会啃出白洞） |

## 4. 程序怎么把它变成「活的」

`js/sea-whale.js`。三层结构，顺序即画序：

```
residue（压暗 + 模糊的旧尾鳍，跟转 55%）
  → fluke（清晰尾鳍，绕尾柄转 ±23°）
  → body（挖掉尾鳍的身体，盖住尾根）
```

**body 必须挖空尾鳍区域**，否则会看到两条尾巴：一条在转、一条钉在原地。
挖空不是硬切，是 `0.28 → 0.34` 的横向渐变，切边半透明，转起来自然叠合。

**residue 必须真的模糊**（缩小 1/10 再放大）。只压暗不模糊的话，
它是「第二个清晰的尾巴」，读作重影；糊到认不出轮廓才读作运动模糊。

### 参数（改素材时要重算）

```js
pivots.fluke = [0.35, 0.44]   // 尾柄，必须落在身体内部
tailCut      = [0.28, 0.34]   // 尾鳍/身体的分界带
angFluke     = sin(phase) * 0.4  // 摆幅 23°
```

枢轴是扫 alpha 通道的列剖面定出来的，不是目测：
尾鳍在 `x 0.13~0.28` 只有 140px 高（两片薄叶片），身体从 `x 0.31` 起一下粗到 280px，
转折点就是尾柄。重新生成脚本：`node shots/analyze-pivot.cjs`。

**枢轴一定要在挖空带的右边**。压在挖空带上时，尾巴一转头就落在空地上，
屏幕上表现为「尾柄断裂」。

### 动态清单

| 动态 | 实现 | 参数 |
|---|---|---|
| 尾鳍摆动 | 分件绕枢轴旋转 | ±23°，周期 2.4s |
| 身体游动 | 以颈线为不动点的 skewY 剪切 | ±0.062 |
| 浮沉 | 正弦位移 | 周期 4.6s，±1.1% 屏高 |
| 呼吸 | 整体缩放 | 1.00 ↔ 1.012，周期 6.2s |
| 运动模糊 | 残影层跟转 55% + 模糊 | 烘焙一次 |

浮沉 4.6s 与呼吸 6.2s **故意不整除**，避免同相变成机械抖动。

## 5. 水下雾化（「贴纸感」的解药）

第一版把图接进去之后，鲸像一张高饱和贴纸浮在暗水里。原因是当时只做了「叠一层蓝」——
叠色能压暗，但压不掉对比度。

现在用的是成像模型：

```
C = C物体 × T + C水 × (1 − T)     T = exp(−2.0 × depth)
C水 = (16, 58, 82)
```

`depth=0` 时 T=1（原色）；`depth=1` 时 T=0.14，**86% 的颜色被水色替换**，
细节被吃掉、明暗差被压缩 —— 这才是远处物体该有的样子。

只在烘焙时跑一次（`getImageData` + 循环 + `putImageData`），**不是每帧**。
不能用 `ctx.filter`：移动端极慢，而且 iOS 16.4 以下的 Safari 根本不支持。

## 6. 性能实测

无头 Edge（软件光栅，无 GPU），780×1688 画布：

| 路径 | frame() 耗时 |
|---|---|
| 贴图 | **0.60 ms/帧** |
| 矢量占位 | 1.65 ms/帧 |

贴图比矢量还快 2.7 倍，因为矢量要跑几百条贝塞尔，贴图只是几次 `drawImage`。
60fps 的预算是 16.7ms，余量极大。真机有 GPU 只会更快。

测量方法：`?bench=1` 同步跑 30 帧（不用 rAF，无头浏览器的虚拟时钟会节流它）。

`q=high|mid|low` 画质档、`sprite=img|mock` 真图/矢量占位、`silhouette=1` 纯剪影。
